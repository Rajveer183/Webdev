# Data, content pipeline and editorial review

## Source material

`source/bsc-hons-statistics-data-science-syllabus.pdf` is the B.Sc. (Hons) Statistics & Data
Science syllabus: 114 pages, 8 semesters, 51 course modules including labs. It is git-ignored.
Copy it here to run the pipeline or the full-PDF tests.

What the source contains:
- **Text:** every page has a text layer (Word export), so no OCR is needed.
- **Images:** the only image on each page is a footer strip of faculty signatures. It is personal data, not content, and is never used on the website.
- **Low-text pages:** pages 12, 24, 36, 45, 65, 85 and 104 are semester dividers. Pages 15, 64 and 84 are blank.

## Pipeline

```
PDF ──extract_pages()──▶ page text (pdfplumber; OCR fallback if installed; low-text pages flagged)
    ──parse_syllabus()─▶ modules: name, code, L-T-P, type, semester, description, objectives,
                         outcomes, units (number, lectures, title, content), practicals,
                         e-learning links, books, source pages, warnings
    ──ingest_pdf()─────▶ SourceTopic rows (status = pending_review) + IngestionRun record
```

Run it from `backend/`:

```bash
python -m app.cli ingest-pdf ../data/source/bsc-hons-statistics-data-science-syllabus.pdf --no-db
#   → data/extracted/syllabus_extracted.json   (114 pages, 51 modules)
python -m app.cli ingest-pdf ../data/source/bsc-hons-statistics-data-science-syllabus.pdf
#   → also stores topics in the database for review in Admin → PDF topics
```

You can also upload the PDF in **Admin → PDF ingestion**.

How ingestion treats topics:
- Ingested topics are never published automatically.
- Re-ingesting refreshes the extracted data but keeps every review decision.

How course types are read: the Core/DSE/AEC/SEC/OE tick sits in a table cell that text extraction
scrambles (the tick is often wrapped below its label). The pipeline therefore reads the tick from
character positions: the first tick at or just below the label row belongs to the rightmost label whose
left edge is not to the right of the tick. All 51 modules resolve (28 Core, 17 DSE, 5 SEC, 1 AECC)
with no warnings; if layout and text disagree, a warning is recorded for review.

## Curated content (what the website shows)

| File | Records | Notes |
|---|---|---|
| `content/services.json` | 14 consulting services | problems, audience, client inputs, process, deliverables, methods, tools, applications |
| `content/courses.json` | 22 certificate courses | modules from syllabus units, labs → projects, proposed durations, completion certificate only |
| `content/workshops.json` | 9 corporate workshops | objectives, topics, formats, example agendas, customisation |
| `content/articles.json` | 21 knowledge articles | KaTeX formulas, worked examples (arithmetic verified), "In practice" notes |
| `content/projects.json` | 7 demo projects | **generated** by `scripts/build_projects.py` from seeded synthetic data |
| `content/topics.json` | 41 catalogue topics | the internal content catalogue (37 approved, 3 pending review, 1 excluded) |
| `content/site.json` | homepage blocks | expertise areas, industries (with source pages), audiences, approach, methodology, FAQ |

- **Schema and slug registry:** `content/SCHEMA.md` holds the schema, the integrity rules and the shared slug registry.
- **Validation:** `python -m app.cli check-content` validates every file and cross-reference.
- **Loading into the database:** `python -m app.cli seed --overwrite` reloads the files. Without `--overwrite`, existing records and admin edits are kept.

## Content catalogue (PDF analysis deliverable)

`catalogue/content-catalogue.md` is generated by `python -m app.cli catalogue-report`.

For every syllabus module it lists:
- topic, description and source pages;
- opportunity types (consulting, course, workshop, project, research support, article, demo);
- related services, courses and articles;
- audience, prerequisites, applications and tools;
- website section and review status, with notes.

### Review decisions recorded in the catalogue

- **Excluded:** Operating System (p82–83). It is not relevant to a statistics consultancy.
- **Pending review:**
  - Discrete Mathematics (p56–57) and Graph Theory (p80–81): candidates for articles or an optional maths module.
  - Introduction to AI (p96–97): only partly relevant (search and knowledge representation).
- **Source ambiguities that were handled:**
  - **SQC & Demography (p43):** contains no demography units, so only SQC is offered.
  - **Financial Mathematics (p109):** the description promises CAPM, Black–Scholes and actuarial exam topics that are not in its units. Only the unit topics are used, with a "not investment advice" note.
  - **Data Visualization (p78):** the description refers to a third-party certification programme. That text is not used.
  - **ML-I Lab practical list (p39–40):** garbled in the source; only clearly legible items are used.
  - **Other quirks:** several copy-paste anomalies in course outcomes, all noted in `topics.json`.

## Demonstration projects

```bash
python data/scripts/build_projects.py      # needs numpy + scipy (build-time only)
```

All seven projects use synthetic data generated with seed `20231004`. Every figure shown on
the site is computed by this script:
- decomposition and forecast MAPE;
- control limits;
- Kaplan–Meier curves and the log-rank test;
- regression coefficients and confidence intervals;
- PCA eigenvalues and loadings;
- ANOVA with Tukey HSD;
- LP optimum and shadow prices.

They are labelled as synthetic demonstrations everywhere they appear.
